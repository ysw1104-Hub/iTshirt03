SW응용 Git·GitHub 핵심정리
자료: 제공된 교재 사진의 Git 기초, SourceTree 실습, 파일 상태 설명

1. Git, GitHub, SourceTree, VS Code의 역할
Git은 파일의 여러 버전과 이력을 내 컴퓨터에서 관리하는 도구다. GitHub는 Git 저장소를 온라인에 보관하고 공유하는 서비스다. SourceTree는 Git 작업을 버튼과 그래프로 다룰 수 있는 GUI 프로그램이고, VS Code는 파일을 만들고 수정하는 편집기다. 같은 저장소를 Git Bash와 SourceTree에서 함께 사용할 수 있다.

2. 작업 공간 → 스테이지 → 로컬 저장소
작업 공간(working directory)은 실제 파일을 열고 수정하는 곳이다. 스테이지(stage)는 다음 커밋에 담을 파일의 내용을 선택해 두는 곳이다. 커밋하면 선택한 내용이 로컬 저장소의 버전으로 기록된다. 프로젝트 안의 숨김 폴더인 .git에는 커밋 이력, 스테이지 정보, 원격 저장소 주소 등 Git 관리 정보가 들어 있다. 기존 저장소를 SourceTree에 Add하는 것은 이 저장소를 프로그램에 등록하는 작업이다.

3. add, commit, push의 차이
git add는 현재 파일 내용을 스테이지에 반영한다. git commit은 스테이지의 내용을 하나의 버전으로 로컬에 기록한다. git push는 로컬에 기록한 커밋을 원격 저장소에 전송한다. 파일을 편집기에서 저장하는 것과 커밋하는 것은 별개의 단계다. 커밋 메시지는 변경 목적을 알아볼 수 있도록 쓴다.
예: README.txt 수정·저장 → git add README.txt → git commit -m "설명 업데이트" → git push origin main

4. clone과 pull의 차이
git clone은 원격 저장소의 파일과 버전 이력을 받아 새로운 로컬 저장소를 만든다. git pull은 이미 있는 로컬 저장소에 원격 저장소의 새 커밋을 가져와 반영한다. 교재의 흐름은 cat 저장소를 원격에 올리고, oct 저장소로 clone한 뒤, oct의 새 커밋을 cat에서 pull하는 것이다. ZIP 다운로드는 Git의 버전 이력을 함께 받는 clone과 다르다.

5. 커밋은 프로젝트 상태를 담은 스냅샷
커밋은 바뀐 줄만 적어 둔 메모가 아니라 해당 시점의 프로젝트 상태를 나타내는 스냅샷이다. 변경된 파일은 그 버전의 전체 내용이 저장되고, 바뀌지 않은 파일은 기존 내용을 재사용한다. 따라서 매번 모든 파일의 새 복사본을 만드는 것으로 이해하면 안 된다. SourceTree에 바뀐 줄이 보이는 것은 Git이 커밋 사이의 차이를 계산해 보여 주기 때문이다.

6. 파일의 네 가지 상태
추적 안 됨(untracked): 새로 만들어 아직 Git 관리 대상으로 추가하지 않은 파일.
스테이지됨(staged): 다음 커밋에 담을 내용이 선택된 파일.
수정 없음(unmodified): 커밋된 내용과 같은 상태의 파일.
수정함(modified): 이미 추적 중인 파일을 고쳐 커밋된 내용과 달라진 상태.

기본 흐름:
새 파일(untracked) --add--> staged --commit--> unmodified
unmodified --파일 수정--> modified --add--> staged --commit--> unmodified

add 후 파일을 다시 고치면 그 수정분은 다시 add해야 다음 커밋에 포함된다. push는 커밋을 전송하는 작업이며, 저장하지 않은 파일이나 스테이지의 내용을 직접 올리는 작업이 아니다.

7. main과 origin/main이 가리키는 것
main은 로컬 브랜치 이름이다. origin은 연결한 원격 저장소에 붙인 이름이다. origin/main은 로컬에서 알고 있는 원격 main 브랜치의 위치를 나타낸다. 새 커밋을 로컬에서 만들면 main이 앞으로 이동하고, push 후에는 main과 origin/main이 같은 커밋을 가리키는지 확인할 수 있다. 다른 곳에서 변경했을 수 있으므로 웹의 최신 상태와 항상 같다고 단정하지는 않는다.

8. cat·oct 역할 실습과 명령 정리
iTshirt-cat과 iTshirt-oct는 한 사용자가 고양이와 문어 역할을 나누어 사용하는 두 로컬 저장소다. 같은 원격 저장소를 매개로 push와 pull의 흐름을 연습하기 위한 구성이다. README의 고양이·문어 이름은 교재 예제의 개발자 목록이다.

git init                         현재 폴더를 Git 저장소로 초기화
git config user.name "이름"      커밋 작성자 이름 설정
git config user.email "이메일"   커밋 작성자 이메일 설정
git add README.txt               파일 내용을 스테이지에 반영
git commit -m "변경 설명"        로컬 커밋 생성
git log                          커밋 이력 확인
git checkout <커밋 ID>            해당 커밋의 상태 확인
git checkout -                   직전 브랜치·위치로 돌아가기
git remote add origin <주소>     원격 저장소 연결
git branch -M main               현재 브랜치 이름을 main으로 설정
git push origin main             원격 main으로 커밋 전송
git clone <주소> <폴더>          새 폴더에 저장소 복제
git pull origin main             원격 main의 변경 내용을 가져와 반영

교재는 git config --global 예시도 보여 준다. --global은 사용자 전체에 적용하고, 생략한 저장소별 설정은 해당 저장소에 적용한다. 커밋 ID와 저장소 주소는 책의 값을 복사하지 않고 본인 환경의 값을 쓴다. SourceTree의 스테이징·커밋·Push 버튼도 같은 Git 작업을 수행한다.

교수님이 물어볼 수 있는 질문

Q. 파일을 저장했는데 GitHub에는 왜 안 보이나요?
A. 저장 후 add와 commit으로 버전을 만들고 push해야 원격에 반영된다.

Q. add와 commit을 왜 나누나요?
A. 여러 변경 중 이번 버전에 담을 내용을 먼저 선택하기 위해서다.

Q. commit하면 인터넷에 올라가나요?
A. 커밋은 로컬에 기록된다. 원격 전송은 push 단계다.

Q. clone과 pull은 언제 사용하나요?
A. 새 로컬 저장소를 받을 때 clone, 이미 있는 저장소를 갱신할 때 pull을 쓴다.

Q. 안 바뀐 파일도 매 커밋마다 새로 복사하나요?
A. 스냅샷에는 그 파일의 상태도 포함되지만, 내용이 같으면 기존 저장 내용을 재사용한다.

Q. main과 origin/main이 서로 다른 커밋에 있으면 무슨 뜻인가요?
A. 로컬 브랜치와 로컬에서 알고 있는 원격 브랜치 위치가 다르다는 뜻이다. 어느 쪽이 앞섰는지 이력을 확인해야 한다.

Q. cat과 oct는 실제 다른 사람이 작업한 것인가요?
A. 한 사용자가 두 폴더로 역할을 나누어 원격 공유 흐름을 연습하는 구성이다.
